# WattWise cloud sync

Account-owned appliances, daily usage, saved bills including original images, POP transitions/rates/sessions/splits, and language/theme/rate preferences sync to Firestore at wattwise_users/{Firebase UID}/records. Only the matching verified Firebase user can access this path. The public appliance catalog retains its previous rules.

SQLite remains the offline store. Transactional SQLite triggers maintain an outbox, including deletion tombstones. Local pending edits survive app restart. On initial migration, server records take precedence over pre-sync local copies with the same key; previously absent local records are uploaded. Later concurrent edits use server commit order (last successfully synced edit wins per record). Different records merge independently. Keep the app open and connected until Settings says Cloud sync up to date before switching devices or clearing storage. Sync checks automatically every 30 seconds, after app edits, and via Sync now. This is not a background operating-system backup service.

Large records are UTF-8/base64 encoded and split into private versioned Firestore parts before the manifest is atomically published. Readers only apply complete records. Superseded image parts are cleaned after commit; interrupted uploads or failed cleanup may leave private orphaned parts for a future maintenance/deletion request. Tombstones remain to prevent offline devices resurrecting deleted records. Max encoded record size is 72 million characters; oversized records remain local with pending sync status. This storage consumes Firestore storage/read/write quota; unchanged images are not repeatedly downloaded. No AI request is made for sync.

Passwords, chat session history, local API budget counters, policy acceptance receipts and the old shared pre-account database are excluded. The privacy policy was versioned to 2026-11-12-cloud-sync, and sync begins only after acceptance. Existing account-scoped data uploads when the updated app is opened and its policy accepted.

Validation: SQLite two-device simulations cover initial restore, large bill images, deletion propagation, retained pending edits, concurrent acknowledgement, preference filtering, and migration. Firebase Rules REST tests cover owner access, other-user denial, anonymous denial, unverified denial, chunk ownership, malformed table rejection and preserved catalog read access. Real two-phone sign-in/restore should still be tested with the APK; no phone installation was performed.
