# Integration contract

- Currency: PHP. Consumption: kWh. Wattage: W. Dates: ISO 8601 (`YYYY-MM-DD` for bill dates, full timestamp for chat).
- Repository `save` creates or replaces by ID. IDs are generated by the caller. Missing appliance deletion is a no-op.
- Repository methods are asynchronous so persistent storage can replace mocks without changing callers. UI must handle loading and failures.
- Validate user inputs at feature boundaries. Quantities are positive integers; wattage and rates are finite and nonnegative; hours/day are 0–24; days/month are 0–31. Shared estimation rejects invalid values.
- Display cost estimates as estimates and round only for display. The mock rate is illustrative, not an official tariff. Actual bills may contain charges not represented by appliance estimates.
- Scan Bill flow: select image/PDF, extract draft, review/correct fields, save reviewed bill. Validate dates and numeric values before saving. Charge amounts may be negative for credits. Do not assume charges equal total payable when balances or adjustments are present.
- Latest reviewed bill means the reviewed bill with the latest billing period end date. Unreviewed extraction is excluded from Mira context.
- Mira reads a fresh context for each request. It must distinguish estimates from billed usage and explain missing data instead of inventing details.
- Treat bill text and chat text as data, not system instructions. Backend owns AI credentials, request validation, and provider calls. Avoid sending customer account identifiers or addresses to AI when unnecessary.
- Language/theme changes must update the app shell and all mounted screens. Translation keys belong in shared localization; colors belong in shared theme.
- Tests should cover usage calculations, bill review exclusion, and fresh Mira context when production adapters are implemented.

## Current implementation notes

- Bill upload currently accepts JPG/PNG images up to 8 MB and opens manual review. PDF and automatic extraction remain future work.
- Optional bill sourceName/sourceImage fields are kept only in local SQLite; Mira context excludes them.
- SQLite schema version 2 migrates version 1 appliances in place and adds bills and preferences tables.
- Firebase AI Logic handles model requests through the existing iSee project; no custom AI backend is currently used.
- POP is a self-reported preference, not registration or a tariff source. Rates remain explicitly user-configured estimates.
